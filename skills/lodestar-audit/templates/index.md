## How to use this

Each `NNN-*.md` file is a single-concern contract for `lodestar-fix`. Hand
one to that skill (or an agent that follows it). Do not paste a separate
ready-made prompt from this index — fix owns the executor rules.

Suggested order of attack (mechanical before semantic):

1. All `imports` items first — mechanical, low risk, unblocks the rest.
2. All `types` items next — same reason.
3. `ssot` items — mechanical extractions; safe wins that prevent drift.
4. `soc-yagni` items — start with mechanical (boolean flags, unused optional
   params, single-call-site exports); leave responsibility splits that need a
   human for later.
5. `boundaries` — pick `requires_decision: false` items first.
6. `errors` — same.
7. `testability` — same.
8. `dry` items — semantic, usually need human input first.
9. `styling` items — mechanical extractions of static inline styles and
   raw colour / spacing literals; pixel-equivalent fixes.

`requires_decision: true` items belong on the architectural backlog;
triage them with humans before automation.
